# Storage Emissions Model

Code accompanying the paper "From marginal emission factors to storage dispatch: a transparent framework for assessing the emission impact of battery operation in electricity markets" (citation below).
Does a grid-scale battery reduce or increase CO2 emissions when it
operates in a day-ahead electricity market, and how does the answer
change with how the battery is dispatched? The model reconstructs an
hourly marginal emission intensity (MEI) signal from public market data
and compares profit-maximising, emission-minimising, and lexicographic
dispatch strategies against a greedy benchmark, using the Netherlands
(EPEX BZN|NL) as the case study.

For the full methodology, see [`model/GUIDE.md`](model/GUIDE.md).

## Requirements

Python 3.10+ (tested on 3.14).

```bash
pip install -r requirements.txt
```

`numpy`, `pandas` for the core model in `model/` (pure computation, no
plotting dependency); `matplotlib`, `openpyxl` additionally for the
paper-specific figure/table scripts in `support/`.

## Data access

Most input data ships in `data/raw/`. Three commodity-price series (EU
ETS carbon, TTF gas, API2 coal) are licensed and are not included - see
[`docs/DATA_ACCESS.md`](docs/DATA_ACCESS.md) for sources and
reconstruction steps, and `support/validate_commodity_data.py` to check
your rebuild against the paper's dataset before running the model.

## How to run

```bash
pip install -r requirements.txt
python model/run.py
```

Runs the full pipeline for the period set in `run.py`'s `CONFIG` section
(default: 2022): loads the data, reconstructs the MEI curve, runs all
five dispatch strategies, and writes results (dispatch CSVs, `mei_curve.csv`,
`summary.csv`) to `data/processed/model/`, plus a console summary. This is
purely computational - `model/` produces numbers, not figures.

## Expected output

Console summary for 2022:

| Strategy | Revenue [EUR] | Net CO2 [tCO2] |
|---|---|---|
| Profit max (DP) | 149,215.0 | 125.26 |
| Emission min (DP) | -23,234.0 | -544.07 |
| Lexico-E (emission primary) | -1,263.0 | -544.07 |

## Reproducing the paper's figures and tables

All figures and tables in the manuscript - including Figure 4, the
validation against Schram et al. (2019) - are built by
`support/produce_paper_figures.py`. It reads data written by several
upstream `support/` scripts, so the full reproduction sequence is:

```bash
python model/run.py                              # dispatch_profit_greedy.csv, mei_curve.csv (2022)
python support/run_paper.py                       # multi-year dispatch, annual_results_*.csv
python support/run_cem_generality_sweep.py        # cem_generality.csv (Figure F1)
python support/run_final.py                       # Appendix E, Table F2
python support/run_robustness.py                  # Table F1 (robustness/sensitivity)
python support/run_lexico_tie_mechanism_check.py  # tie-mechanism stats (Sections 4.3, 5)
python support/produce_paper_figures.py           # Figures 2-10 & F1, Tables 1-4, appendix legends
```

This runs the full 2018-2025 multi-year sweep and takes on the order of
hours, not minutes - the model/run.py quick-start above is the fast path
if you only want the headline numbers. Each script prints its own
progress and writes into `data/processed/model/`.

## Repository layout

```
model/    Distributable model - reusable for any bidding zone, pure computation
support/  Paper-specific scripts: sensitivity sweeps, robustness checks, figures/tables
data/     raw/ (inputs) and processed/ (outputs, generated by running the code)
docs/     Data provenance, plant sourcing, and data-access instructions
```

## Adapting to a different bidding zone

`run.py`'s `CONFIG` section is the only place to edit: replace the three
input CSVs (plant stack, commodity prices, day-ahead prices) with your
zone's data and update `FUEL_PRICE_MAP` if your price columns are named
differently. No changes to `market.py`, `storage.py`, or `algorithms.py`
are needed. See "How to adapt to a different bidding zone" in
[`model/GUIDE.md`](model/GUIDE.md).
